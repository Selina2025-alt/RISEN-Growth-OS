## 1. 为什么内容归因需要特殊处理

内容平台（微信公众号/知乎/CSDN）的归因和电商/广告归因完全不同：

- **电商归因**：用户旅程清晰（点击→加购→支付），归因目标是找出哪个触点贡献了转化
- **内容归因**：目标不是追踪用户路径，而是判断**哪类内容在哪个平台更有效**

Agent 9 的归因问题是：**一篇具体文章在某个平台的表现，是否说明同选题的其他文章也会在同类平台有类似表现？**

这是内容归因，不是用户旅程归因。

## 2. 为什么不直接用 CTR 的绝对值比较

### 2.1 不同平台基准 CTR 差异巨大

| 平台 | 平均 CTR | 说明 |
|------|---------|------|
| 微信公众号 | 2.5% | 订阅列表打开率 |
| 知乎 | 3.5% | 推荐feed曝光点击率 |
| CSDN | 3.0% | 搜索结果点击率 |
| Dev.to | 2.0% | 首页推荐点击率 |
| LinkedIn | 2.0% | feed曝光点击率 |

**问题**：微信公众号 CTR=4% 和知乎 CTR=4%，含义完全不同：
- 微信 4%：超过平均 60%，非常好的文章
- 知乎 4%：仅超过平均 14%，一般般的文章

### 2.2 平台 CTR 的波动性不同

| 平台 | 平均 CTR | 标准差 | 波动系数（std/mean） |
|------|---------|--------|----------------------|
| 微信公众号 | 2.5% | 1.5% | 60% |
| 知乎 | 3.5% | 2.0% | 57% |
| LinkedIn | 2.0% | 1.0% | 50% |

波动性不同，使得"超过平均 1%"在不同平台的统计意义完全不同。

## 3. Z-Score 标准化方法

### 3.1 公式

```
Z_i = (CTR_i - μ_platform) / σ_platform

其中：
- Z_i = 某篇文章的 Z-Score
- CTR_i = 该文章的点击率
- μ_platform = 该平台的平均 CTR（来自平台基准数据）
- σ_platform = 该平台 CTR 的标准差（来自历史数据统计）
```

### 3.2 Z-Score 的含义

| Z-Score | 含义 | 统计意义 |
|---------|------|---------|
| Z ≥ 2.0 | 超过平台平均 2 个标准差 | 极端优秀，p < 0.05 |
| Z ≥ 1.0 | 超过平台平均 1 个标准差 | 显著优秀，p < 0.16 |
| -0.5 ≤ Z < 1.0 | 在平均附近 0.5 个标准差内 | 正常波动 |
| -1.5 ≤ Z < -0.5 | 低于平台平均 0.5~1.5 个标准差 | 显著较差 |
| Z < -1.5 | 低于平台平均 1.5 个标准差 | 极端差，p < 0.07 |

### 3.3 为什么选 Z=1.0 作为 SCALE 阈值

GrowthBook 和行业 A/B 测试实践通常以 Z=1.0（约 p=0.16）作为"值得关注"的信号。

这不是说 p<0.05 才有意义——对于内容运营迭代速度来说，Z=1.0 的信号足够强，可以作为"扩大投入"的依据。

**如果决策错误**，浪费的是几篇文章的产出成本，远低于错过一个有效选题的机会成本。

### 3.4 跨平台 Z-Score 的计算

当一个 Topic 的文章分布在多个平台上时，需要计算**加权平均 Z-Score**：

```
Z_weighted = Σ(Z_i × impressions_i) / Σ(impressions_i)

以曝光量为权重，因为高曝光文章的 Z-Score 更可靠
```

**为什么这样加权**：一篇 10000 曝光的爆款的 Z-Score 比 100 曝光的冷文更有说服力。

### 3.5 Position-Based Attribution（U-Shaped）说明

**40%/20%/40% 是经验规则，非理论最优。**

来源：
- 注意力衰减理论：用户在漏斗两端（首触、临转化前）注意力最集中
- Google Analytics 早期推广为"首尾优先"的实践默认值
- Google 2016 白皮书：实证证明首尾贡献最大，但具体比例是经验值，非理论最优

Agent 9 的 position_based 模型保留此配置，**仅作实验对比用**，不作为严谨统计依据。

## 4. 为什么不用 Bayesian 方法

Bayesian 方法需要：
1. **先验分布（Prior）**：在看到数据之前对 CTR 分布的假设
2. **似然函数（Likelihood）**：数据在给定 Prior 下的概率

**为什么不直接用**：
- 先验的选择会显著影响结果，但当前没有足够数据来确定合理的 Prior
- v2.1 阶段，我们更关心"这个选题是否比平台平均更好"，Z-Score 已经足够回答这个问题
- Bayesian 适合 A/B 测试场景（两种变体的比较），而非平台基准比较场景

**何时升级到 Bayesian**：当 Agent 9 积累了大量真实 CTR 数据后，可以：
1. 用真实 CTR 数据拟合 Beta 分布作为 Prior
2. 对每个 Topic 的 CTR 做 posterior 预测
3. 直接计算 P(CTR > platform_avg)

## 5. 最小样本数判断

### 5.1 为什么需要最小样本

CTR 是一个比率统计量，分子是 clicks，分母是 impressions。当样本很小时：

- 1 篇文章，100 曝光，5 点击 → CTR=5.0%，Z=1.67，SCALE
- 但这只是随机波动，不是真实信号

### 5.2 业界最小样本标准

| 场景 | 最小曝光量建议 | 说明 |
|------|--------------|------|
| Google Analytics | 每组 1000 曝光 | 通用参考 |
| Optimizely（A/B测试） | 每组 1000 conversions | 针对转化率优化 |
| GrowthBook | 每组 1000 曝光 | 内容CTR场景 |

Agent 9 采用 **5 篇文章**作为最小样本判断依据（而非曝光量），原因是：
- 文章数比曝光量更直观可控制
- 5 篇文章 × 平均每篇 5000 曝光 ≈ 25000 总曝光，符合统计要求

### 5.3 冷启动策略

新 Topic（< 5 篇文章）：
- **不拒绝归因**，但 boost_score 强制 = 1.0（中性）
- **不生成 SCALE/REDUCE/STOP Insight**，避免噪声决策
- 积累到 5 篇后再进入正常归因流程

## 6. Mock 数据的标准差问题

### 6.1 为什么 Mock 也需要标准差

v2.1 的 Z-Score 计算需要每个平台的 stdCTR（CTR 标准差）。

标准差反映的是"平台内文章 CTR 的离散程度"：
- 如果 std=0，所有文章 CTR 都一样，没有比较意义
- 如果 std 很大（相对均值），说明平台文章表现差异大，需要更大的 CTR 差异才能判断"有效"

### 6.2 Mock 标准差的来源

当前 Mock 适配器用以下参数生成 CTR：

```javascript
gaussRandom(mean CTR, stdCTR)
// 微信公众号：gaussRandom(0.025, 0.015) → std/mean = 60%
// LinkedIn：gaussRandom(0.020, 0.010) → std/mean = 50%
```

这些标准差参数：
- **不是行业权威数据**，是工程经验值
- 记录在 `attribution-config.json` 的 `stdCTR` 字段
- **1 年内当真实数据积累后，用真实数据的统计标准差替换**

### 6.3 如何用真实数据计算标准差

当 Agent 9 有了 100+ 篇真实文章数据后，可以：

```javascript
// 计算某平台的真实 CTR 标准差
function computeStdCTR(platformPerformances) {
  const ctrs = platformPerformances.map(p => p.metrics.ctr);
  const mean = ctrs.reduce((s, c) => s + c, 0) / ctrs.length;
  const variance = ctrs.reduce((s, c) => s + Math.pow(c - mean, 2), 0) / ctrs.length;
  return Math.sqrt(variance);
}
```

## 7. 归因模型的局限性

### 7.1 选题质量和执行质量的混淆

Agent 9 归因到**选题**（TopicBoost），但一篇文章的表现是选题质量和执行质量的综合结果：

- **选题好 × 执行差** → 可能 CTR 很低，误判选题无效
- **选题差 × 执行好** → 可能 CTR 很高，误判选题有效

**缓解措施**：Agent 9 的 Insight 同时考虑 CTR 和 CVR。如果 CTR 高但 CVR 低，说明文章有人点但转化差，可能是执行问题而非选题问题。

### 7.2 平台差异和地理因素

一篇文章在微信公众号和知乎的表现可能完全不同：
- 不同平台用户画像不同
- 不同平台的推荐算法不同
- 不同平台的发布时间效果不同

**缓解措施**：`ratio_to_benchmark` 是按平台分别计算后再聚合的，每个平台都和自己在该平台的基准比，而不是跨平台直接比较。

### 7.3 时间因素

发布 1 天后的 CTR 和发布 7 天后的 CTR 差异巨大：
- 公众号文章：72 小时内的 CTR 最高，之后衰减
- 知乎回答：搜索流量是长期的，可能 30 天后还在被阅读

**缓解措施**：`minAttributionWindow` 为每个平台设置了最小归因等待时间，在此之前不纳入归因计算。
